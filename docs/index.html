MeshCore → Meshtastic Beacon

A MeshCore repeater that periodically announces itself on a Meshtastic network.

What it is

A native MeshCore advert is invisible to Meshtastic: the two use different LoRa sync words and incompatible framing, so a Meshtastic node hears the RF energy and drops it. This add-on makes a MeshCore repeater briefly speak Meshtastic — it retunes to the Meshtastic channel and emits real Meshtastic packets, then retunes back. Each beacon sends three packets in one hop:

  • NodeInfo — the repeater appears as a named node in Meshtastic apps, named MC <repeater name>.
  • Position — a pin on the Meshtastic map, using the repeater's configured location (skipped if unset).
  • Text — the announcement line, e.g. MeshCore repeater in range.

It is still a one-way beacon — it doesn't route Meshtastic traffic. Because LoRa is single-channel, the repeater is briefly off the MeshCore channel during each beacon, so beacons are infrequent (default every 5 minutes) and only fire when the mesh is idle.

Quick start

  1. Download the image for your board below and flash it (see per-platform notes).
  2. Connect to the repeater's serial console (115200 baud) or an admin remote-CLI session.
  3. Run mtbeacon on to enable, then mtbeacon send to fire one immediately.
  4. Confirm a Meshtastic device on US LongFast shows the text.

On boards with a screen, the boot splash reads < Repeater +Beacon > (instead of < Repeater >) so you can tell at a glance you're running this variant. The home screen then shows a live status line — Beacon ON 5m (green) or Beacon off (red) — that updates as you change settings.

Flashing notes

nRF52 (.zip) — T114, RAK4631, RAK3401, WisMesh Tag. Easiest is the official MeshCore web flasher (see the MeshCore flashing docs for the current URL). Or via DFU:

adafruit-nrfutil dfu serial \
  --package meshcore-mtbeacon-<board>.zip \
  -p /dev/ttyACM0 -b 115200

RP2040 (.uf2) — RAK11310. Hold BOOTSEL while plugging in USB; a RPI-RP2 drive appears. Drag the .uf2 onto it; it reboots into the firmware.

ESP32-S3 (.bin) — RAK3112, Heltec V3/V4, Station G2. Use the web flasher, or esptool at the app offset for the standard MeshCore layout (substitute your board's file):

esptool.py --chip esp32s3 \
  write_flash 0x10000 \
  meshcore-mtbeacon-rak3112.bin

Verify the offset against your board's MeshCore partition layout.

STM32WL (.bin) — RAK3x72. STM32CubeProgrammer, or st-flash:

st-flash write \
  meshcore-mtbeacon-rak3x72.bin 0x08000000

CLI reference

Over serial (115200) or an authenticated admin remote-CLI session:

CommandEffect
mtbeaconshow current config & derived node id (same as status)
mtbeacon helplist all commands (detailed list prints to serial)
mtbeacon on / offenable / disable periodic beaconing
mtbeacon sendtransmit one beacon now (works even when off)
mtbeacon interval <min>period between beacons, 1–1440
mtbeacon preset <name>modem preset — LongFast, MediumFast, ShortFast, ShortTurbo, …
mtbeacon region <name>region/country band — US, EU_868, ANZ, JP, … (alias country)
mtbeacon freq <MHz|auto>manual frequency override; auto re-derives from region+preset
mtbeacon power <dBm>TX power, −9…22 (auto-capped to the region's legal limit)
mtbeacon text <string>announced text, ≤63 chars
mtbeacon nodeinfo on/offalso emit a NodeInfo (named node) — default on
mtbeacon position on/offalso emit a Position (map pin) — default on
mtbeacon presets / regionslist the available preset / region names

Region + preset auto-tune the frequency. Setting region or preset computes the exact Meshtastic default-channel frequency the same way Meshtastic firmware does (the preset's bandwidth sets how many channel slots fit in the region band; the channel name hashes to a slot). So mtbeacon region EU_868 then mtbeacon preset MediumFast lands on the frequency EU MediumFast nodes actually listen on — no manual math. Use mtbeacon freq <MHz> only to override; freq auto reverts.

Settings persist to /mtbeacon in the internal filesystem, separate from core NodePrefs (core is untouched). Defaults: US 915 LongFast, 5-minute interval, disabled until mtbeacon on. The Meshtastic node number is derived from the repeater identity, so it is stable across reboots.

How the packet is built

For the default public LongFast channel, the pieces are small and well-known:

  • Header (16 bytes): broadcast dest 0xFFFFFFFF, sender node id, packet id, flags (hop limit), and the channel hash (0x08 for the default channel).
  • Payload: a protobuf Data{ portnum=TEXT_MESSAGE_APP, payload=text }, AES-CTR encrypted with the well-known default channel key.
  • Radio: retuned to LongFast (BW 250 kHz, SF 11, CR 4/5) and sync word 0x2B for the transmit, then restored to the repeater's MeshCore parameters.

Caveats & etiquette

  • Region. Default is US. For another region run mtbeacon region <name> — it auto-tunes the frequency and applies the region's power cap. Transmitting outside your permitted band/power is still your responsibility.
  • You appear as a node. NodeInfo/Position make the repeater show up on other people's Meshtastic maps and node lists. That's the point, but turn it off (nodeinfo off / position off) if you'd rather just send the text.
  • Shared spectrum. A beacon adds airtime to someone else's public channel. Keep the interval long, respect duty-cycle limits, and don't beacon onto channels you don't operate.
  • One-way only. It announces presence; it does not route Meshtastic traffic or appear as a full node.
